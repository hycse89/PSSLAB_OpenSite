
## 26장. 비용 최적화·모델 라우팅·캐시 전략: “품질 유지 + 비용 절감”을 동시에 달성하는 운영 레버

### 1) 개요: AI 비용은 “모델 단가”가 아니라 **아키텍처 습관**에서 결정된다

AI 서비스는 성능이 올라갈수록 보통 비용도 같이 오릅니다(더 큰 모델, 더 긴 컨텍스트, 더 많은 툴 호출). 그래서 24장은 “싸게 하자”가 아니라:

> **품질을 떨어뜨리지 않고 비용을 줄이는 구조**를 만든다

여기서 다루는 레버는 다음 5가지입니다.

1. **요청을 분류하고(라우팅)** 큰 모델은 꼭 필요할 때만 쓰기
2. **캐시**로 반복 요청/반복 컨텍스트를 줄이기
3. **컨텍스트/토큰 절감**으로 매 호출 비용을 낮추기
4. **배치/서빙 최적화**로 GPU 효율을 올리기
5. **관측+예산(guardrail)**로 비용 폭주를 막기

---

## 2) 학습 목표

1. 비용을 토큰/검색/툴/서빙(GPU)로 분해해 어디서 새는지 찾기
2. 모델 라우팅(작은 모델→큰 모델 escalation) 전략을 설계
3. 프롬프트/컨텍스트 캐시와 RAG 캐시를 안전하게(권한 분리) 적용
4. RAG에서 컨텍스트 압축/리랭크/쿼리 최적화로 비용을 낮추는 방법 이해
5. “예산 제한 + 서킷브레이커 + 릴리즈 게이트”로 비용을 통제

---

## 3) 비용 구조 분해: 무엇이 돈을 먹는가

### 3.1 LLM 토큰 비용

* 입력(시스템 프롬프트 + 컨텍스트 + 사용자 질문)
* 출력(생성 길이)
* 스트리밍은 UX를 좋게 하지만, 토큰 자체를 줄이지는 않습니다.

### 3.2 RAG 비용

* 임베딩 생성(문서 인덱싱 + 쿼리 임베딩)
* 검색(벡터DB/하이브리드/BM25)
* 리랭크(특히 cross-encoder/LLM rerank는 비용 큼)
* 컨텍스트 길이 증가(LLM 비용 증가로 직결)

### 3.3 Tool 비용

* 외부 API 비용(지도, 번역, 결제, DB)
* 툴 호출 횟수 폭주(에이전트 루프)
* 실패 재시도 비용(타임아웃/오류)

### 3.4 인퍼런스 인프라 비용

* GPU 시간(서빙 엔진 효율에 따라 비용이 크게 달라짐)
* 스케일링/유휴 시간(낮은 이용률이 비용 폭탄)

---

## 4) 핵심 전략 1: 모델 라우팅(Model Routing) & Escalation

### 4.1 라우팅이란

모든 요청을 최고급 모델로 보내지 말고,

* **쉬운 요청은 작은/저렴한 모델**
* **어려운 요청만 큰/비싼 모델**
  로 보내는 전략입니다.

### 4.2 라우팅 기준(실무에서 잘 먹히는 신호)

* 질문 길이/복잡도(짧은 FAQ vs 복잡한 분석)
* 도메인/리스크 등급(정책/법무는 상위 모델)
* RAG 검색 결과의 “확신도”(Top-1 점수, 근거 다양성)
* 출력 요구(구조화 JSON, 긴 보고서, 코드 생성)
* 안전 필요도(민감/고위험은 보수 모드 + 검증)

### 4.3 2단/3단 escalation 패턴(추천)

* 1단: 작은 모델로 시도(요약/분류/간단 답)
* 실패 조건(예: 근거 부족/스키마 실패/낮은 확신도) 발생 시
* 2단: 중간 모델 + rerank/압축 강화
* 3단: 최고 모델 + HITL(필요시)

**중요**: 실패 조건은 “감”이 아니라 **지표로 정의**해야 합니다.
예: “스키마 검증 실패”, “근거 점수 < 임계값”, “정답률 낮은 질문군”

---

## 5) 핵심 전략 2: 캐시(Cache) — 비용 절감의 왕

캐시는 “정확도 유지 + 비용 절감”을 동시에 만드는 가장 강력한 레버입니다.

### 5.1 캐시의 3종

1. **프롬프트 캐시**: 시스템 프롬프트/정형 템플릿을 재사용
2. **RAG 캐시**: 쿼리→검색 결과(문서 ID/청크) 재사용
3. **결과 캐시**: 최종 답변 자체 재사용(FAQ/정책 Q&A에 강함)

### 5.2 캐시 키 설계(실무 핵심)

* 단순히 “질문 문자열”만으로 키를 잡으면 위험
* 최소한 아래를 포함해야 안전합니다.

  * 테넌트/사용자/권한 스코프(ACL)
  * 인덱스 버전(문서가 바뀌면 캐시 무효화)
  * 프롬프트 버전(프롬프트 바뀌면 무효화)
  * 모델 버전(출력 스타일/정확도 차이)
* TTL(만료) 정책을 두고, 민감정보는 캐시 금지/짧은 TTL

### 5.3 캐시가 특히 잘 먹히는 케이스

* 사내 정책/FAQ 같은 반복 질문
* 보고서 템플릿 기반 생성
* 동일 문서 요약/추출 반복(문서 해시 기반 캐시)

---

## 6) 핵심 전략 3: 토큰/컨텍스트 절감(가장 직접적인 비용 절감)

### 6.1 프롬프트 다이어트

* 시스템 프롬프트를 “긴 설명” 대신 “규칙+예시 최소”로 재작성
* 매번 넣는 공통 안내를 줄이고, 외부 정책은 ID로 참조(내부에서 매핑)

### 6.2 RAG 컨텍스트 최적화(10장 복습 + 비용 관점)

* Top-K 줄이기(대신 rerank로 품질 유지)
* 컨텍스트 압축(필요 문장만)
* 중복 제거(비슷한 청크 제거)
* 질문 재작성으로 검색 정확도↑ → 불필요한 청크↓
* 근거 우선 생성으로 “길게 설명하다 새는 토큰” 감소

### 6.3 출력 길이 제어

* 최대 토큰 제한, 요약/표 중심 출력
* “추가 설명이 필요하면 요청하라” 패턴으로 기본 응답을 짧게

---

## 7) 핵심 전략 4: RAG 비용 최적화(임베딩·검색·리랭크)

### 7.1 임베딩 비용

* 문서 재임베딩을 최소화(증분 인덱싱, 20장)
* 청킹을 너무 잘게 쪼개면 저장/검색/리랭크 비용이 증가

### 7.2 검색 비용

* 자주 쓰는 필터/컬렉션 라우팅으로 탐색 공간 축소(10장)
* 하이브리드에서 sparse를 먼저 써서 후보를 줄이고 dense로 정밀화하는 등 단계화

### 7.3 리랭크 비용

* 무조건 LLM rerank를 쓰지 말고,

  * 가벼운 reranker(또는 cross-encoder)를 1차로,
  * 정말 어려운 케이스만 LLM rerank로 escalation
* 후보 수를 제한(Top-50→Top-10 정도로 줄여 비용 절감)

---

## 8) 핵심 전략 5: 서빙 최적화(17장) + 비용 통제(가드레일)

### 8.1 서빙 효율

* 동적 배치(inflight batching)로 GPU 효율↑
* KV-cache 메모리 관리로 OOM/스왑 비용↓
* 스케일링: 트래픽 패턴에 맞춘 오토스케일, 유휴 GPU 최소화

### 8.2 비용 가드레일(운영 필수)

* 사용자/팀 단위 예산(월/일)과 레이트리밋
* 요청당 최대 토큰/최대 툴 호출 수
* 에이전트 루프 감지 후 강제 종료
* 비용 이상 징후 시 기능 제한(서킷 브레이커)

---

## 9) 비용 최적화의 표준 운영 프로세스

1. **계측**: 토큰, RAG 단계별 비용, 툴 비용, GPU 비용을 분리해서 측정
2. **버킷팅**: 비용 상위 10% 요청을 유형별로 나눔(긴 문서, 멀티모달, 에이전트 루프 등)
3. **레버 적용**: 라우팅/캐시/압축/출력제어를 적용
4. **품질 검증**: 19장 회귀 테스트로 품질 유지 확인
5. **릴리즈**: 카나리 → 확대, 비용/품질 동시 모니터링(17·20장)

---

## 10) 관련 기술·솔루션(비용 최적화에 직접 연결되는 것들)

* **vLLM / TensorRT-LLM / TGI**: 인퍼런스 효율(배치/캐시/최적화)로 GPU 비용을 낮추는 핵심 엔진(17장).
* **Redis**: 결과/세션/RAG 캐시에 널리 사용(권한 스코프 설계 필수).
* **OpenTelemetry + Grafana**: 토큰/지연/비용을 지표화해 비용 폭주를 조기에 감지.
* **Feature Flag(LaunchDarkly 등)**: 비용이 큰 기능을 점진 배포/긴급 차단하는 운영 도구.
* **FinOps 도구(클라우드 비용 관리)**: GPU/스토리지/네트워크 비용을 팀/서비스 단위로 가시화.

---

## 11) 권장 실습(현업형): “비용 30% 절감” 프로젝트 시뮬레이션

### 실습 A: 라우팅 + 캐시로 비용 줄이기

* 요청을 3등급으로 라우팅(FAQ/일반/복잡)
* FAQ는 결과 캐시 적용
* 일반은 작은 모델 + 짧은 컨텍스트
* 복잡은 큰 모델 + rerank/압축
* 전후 비교: 비용/TTFT/P95/정답률/인용 누락률

### 실습 B: RAG 비용 최적화

* Top-K 20→8로 줄이고 rerank 적용
* 컨텍스트 압축으로 입력 토큰 40% 절감
* 리플레이 세트로 품질 유지 확인(19장)

---

## 12) 이 장의 결론(커리큘럼 마무리)

* 비용 최적화는 “값싼 모델로 바꾸기”가 아니라
  **라우팅·캐시·토큰 절감·서빙 효율·가드레일**을 조합하는 시스템 설계입니다.
* 19~23장의 평가/드리프트/거버넌스가 갖춰져야, 비용 최적화를 해도 품질이 무너지지 않습니다.
* 이 24장까지 갖추면, 최신 AI(LLM/비전/음성/문서/시계열)를 “실무 서비스”로 설계·운영하는 전체 로드맵이 완성됩니다.
