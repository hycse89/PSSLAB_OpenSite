
## 16장. 멀티모달 AI: 텍스트·이미지·오디오·비디오를 한 시스템에서 “이해·검색·생성·행동”까지 연결하기

### 1) 개요: 멀티모달은 “입력 포맷이 여러 개”가 아니라, **업무 세계의 신호를 통합**하는 능력

현업 데이터는 대개 섞여 있습니다.
사진(현장/제품), PDF(문서), 음성(회의/콜), 화면(차트/대시보드), 로그(텍스트)… 멀티모달 AI는 이런 신호를 **같이 이해하고**, 필요하면 **근거를 찾고**, 최종적으로 **행동(툴 호출/업무 실행)**까지 연결합니다.

최근 대표 멀티모달 모델/계열 예:

* **OpenAI GPT-4o**: 텍스트·시각·오디오를 실시간으로 함께 다루는 “omni” 멀티모달 모델로 소개됨. ([OpenAI][1])
* **Anthropic Claude 3.5 Sonnet**: 시각 추론(차트/그래프 해석)과 “불완전한 이미지에서 텍스트 전사”를 강점으로 강조. ([Anthropic][2])
* **Google Gemini 1.5**: 장문/장시간 컨텍스트에서 멀티모달 이해와 검색 성능을 강조한 기술 보고서 라인. ([arXiv][3])
* **Meta Llama 3.2 Vision / Llama 4(멀티모달 시스템)**: 오픈 생태계에서 비전 모델과 멀티모달 시스템을 확대(뉴스/공식 블로그). ([메타 AI][4])

---

### 2) 학습 목표

1. 멀티모달 문제를 **(이해/추출)·(검색/RAG)·(생성)·(행동/툴)**로 분해해 설계
2. **VLM(Vision-Language Model)**, **멀티모달 임베딩**, **크로스모달 검색** 개념을 설명
3. “멀티모달이 잘 안 되는 이유”를 **입력 전처리/근거 부족/평가 부재**로 진단
4. Document AI(14장), Video AI(13장), Speech(15장)와 **LLM 워크플로우(11장)**를 하나로 묶는 아키텍처를 설계
5. 운영 관점(비용·지연·보안·감사·평가)을 포함해 제품화

## 3) 핵심 개념: 멀티모달을 4가지 기능 블록으로 보라

### 3.1 멀티모달 “이해”

* 이미지/차트/스크린샷/문서 레이아웃을 보고 **무슨 의미인지** 파악
* 예: “이 그래프 추세를 설명하고 이상치 원인을 추정”

### 3.2 멀티모달 “추출”

* 문서/영수증/이미지에서 **필드/표/엔티티**를 뽑아 구조화(JSON)
* 14장의 Document AI + 7장의 구조화 출력이 결합되는 지점

### 3.3 멀티모달 “검색”

* 텍스트 질문으로 이미지/문서/클립을 찾거나, 반대로 이미지로 관련 문서를 찾기
* 핵심 기술: **멀티모달 임베딩(공간 정렬)** + 벡터 검색

### 3.4 멀티모달 “행동”

* 이해/추출/검색 결과를 바탕으로 **툴 호출(8장)**로 업무 실행
* 예: “영수증에서 총액/거래처 추출 → ERP 등록 API 호출”

---

## 4) 핵심 원리: 멀티모달 아키텍처 3종(실무 감각)

### 4.1 Early Fusion(초기 결합)

* 입력 단계에서 모달을 함께 섞어 처리(큰 모델에서 가능)
* 장점: 모달 간 상호작용이 강함
* 단점: 비용/데이터 요구가 큼

### 4.2 Late Fusion(후기 결합)

* 모달별로 먼저 처리(예: OCR/ASR/비전 모델) → 결과를 LLM이 통합
* 장점: 가장 실무 친화적(전처리/검증/교체가 쉬움)
* 단점: 모달 간 미세 상호작용은 약해질 수 있음

### 4.3 Tool-augmented Fusion(툴 결합형)

* 모델이 필요할 때 **전문 툴(OCR/표추출/ASR/비디오 분석)**을 호출해 근거를 만들고 통합
* 장점: 정확도·감사·운영 안정성 최강(현업 추천)
* 결론: “멀티모달은 모델 하나가 다 한다”보다 **툴+워크플로우**가 먼저 성공합니다.

---

## 5) 멀티모달 RAG: 텍스트 RAG의 확장판

### 5.1 멀티모달 RAG의 기본 패턴

1. 입력(텍스트/이미지/음성)
2. 전처리(OCR/ASR/프레임 샘플링/표 추출)
3. 멀티모달 임베딩 생성(텍스트·이미지·클립)
4. 벡터 검색(필요 시 하이브리드)
5. 근거 압축/정리(중복 제거, 핵심 문장만)
6. 답변 + 출처(페이지/좌표/프레임 타임코드)

### 5.2 실패 원인(현업 Top 5)

* 이미지/문서 전처리(OCR/레이아웃)가 깨짐 → 입력이 이미 실패
* “차트/표”를 텍스트로만 넣어 의미가 훼손
* 비디오를 너무 길게 넣어 컨텍스트가 폭발(→ 샘플링/클립 검색 필요)
* 근거가 있는데 LLM이 **근거를 선택** 못 함(→ rerank/근거 우선 생성)
* 평가가 없음(→ 골든셋 없이 튜닝하면 끝이 없음)

---

## 6) 대표 활용 시나리오(비 LLM 영역과 결합)

### 6.1 문서+이미지+LLM: “영수증/계약서 자동 처리”

* Document AI(OCR/표/레이아웃) → LLM 구조화(JSON) → 검증(합계/세금) → ERP/그룹웨어 툴 호출

### 6.2 비디오+이벤트: “현장 안전/침입 감지”

* 비디오(검출+추적) → 이벤트 조건(시간 누적) → 스냅샷/클립 저장 → 알림/티켓 생성

### 6.3 음성+지식베이스: “회의/콜센터”

* Streaming STT → 요약/액션 추출(JSON) → 고객/주문 DB 조회 툴 → 상담 스크립트 생성 → TTS

---

## 7) 관련 기술·솔루션(최신 대표 스택, 1~2줄)

### 7.1 멀티모달 LLM/VLM

* **OpenAI GPT-4o**: 텍스트·비전·오디오를 실시간으로 함께 처리하는 멀티모달 모델로 소개. ([OpenAI][1])
* **Anthropic Claude 3.5 Sonnet**: 차트/그래프 등 시각 추론과 이미지 텍스트 전사 능력을 강조. ([Anthropic][2])
* **Google Gemini 1.5**: 장문/장시간 컨텍스트에서 멀티모달 이해·검색 성능을 강조한 기술 보고서. ([arXiv][3])
* **Meta Llama 3.2 Vision / Llama 4**: 오픈 생태계 비전 모델(3.2)과 멀티모달 시스템(4) 확장 흐름. ([메타 AI][4])

### 7.2 멀티모달 “전처리 툴”

* **Document AI(클라우드)**: Google Cloud Document AI / Azure AI Document Intelligence / AWS Textract 같은 폼·표·레이아웃 중심 솔루션(14장 참고).
* **비디오 파이프라인**: FFmpeg/GStreamer + (필요 시) GPU 파이프라인(DeepStream)로 디코딩/샘플링/이벤트화를 표준화.
* **음성**: Whisper 계열(배치), 스트리밍 ASR 엔진(NVIDIA Riva 등) + 후처리(용어 사전/핫워드).

### 7.3 멀티모달 RAG/워크플로우

* **LlamaIndex / LangChain**: 문서·인덱스·라우팅·압축 컴포넌트 조립에 유용
* **LangGraph / Temporal**: 멀티스텝(전처리→검색→검증→실행)을 상태 기반으로 안정화

---

## 8) 평가: 멀티모달은 “정답률”보다 “업무 성공률”로 본다

권장 지표 세트:

* **Retrieval**: Recall@K(정답 근거가 Top-K에 있나), 근거 다양성(중복률)
* **Extraction**: 필드 정확도/누락률, 숫자·날짜 오차율, 근거 좌표(페이지/박스) 포함률
* **Agent/Workflow**: 툴 호출 성공률, 재시도 횟수, 승인 필요 케이스 처리율
* **Ops**: 지연(특히 비디오/음성), 비용(토큰·디코딩·스토리지), 보안(권한 필터 통과율)

## 9) 권장 실습(현업형)

### 실습 A: “이미지/문서 혼합” Q&A + 근거 인용

* 입력: 스크린샷(차트/대시보드) + 관련 PDF 일부
* 파이프라인: OCR/레이아웃 → 멀티모달 검색 → 근거 3개만 압축 → 답변 + 페이지/좌표 인용
* 평가: 근거 인용률, 오답 시 원인(전처리 vs 검색 vs 생성) 분리

### 실습 B: “멀티모달 업무 자동화”

* 입력: 영수증 사진
* 처리: 필드 추출(JSON Schema) → 합계 검증 → ERP 등록 툴 호출(모의)
* 평가: 파싱 성공률/필드 누락률/검증 실패율/재시도 비용
