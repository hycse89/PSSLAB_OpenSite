
## 15장. Audio/Speech AI: STT·TTS·대화 시스템을 “지연/정확/운영” 관점에서 설계하기

### 1) 개요: 음성 AI는 모델보다 “파이프라인”과 “지연”이 제품을 좌우한다

Speech AI는 기술적으로는 세 가지 축으로 정리됩니다.

1. **STT(음성→텍스트)**: 회의 녹취, 콜센터, 현장 음성 기록, 자막 생성
2. **TTS(텍스트→음성)**: 안내/상담/내비, 캐릭터 음성, 개인화 음성
3. **Speech-to-Speech(대화형 음성 에이전트)**: 듣고 이해하고(ASR) → 생각하고(LLM) → 말하는(TTS) 실시간 시스템

실무에서 가장 중요한 건 “모델이 얼마나 똑똑한가”보다:

* **지연(latency)**: 대화는 1~2초만 늦어도 UX가 붕괴
* **도메인 정확도**: 고유명사/제품명/전문 용어를 얼마나 잘 듣는가
* **잡음/환경 내성**: 공장/차량/현장/콜센터 품질 편차
* **운영/보안**: 녹취 데이터, 개인정보(PII), 저장/마스킹, 감사

이 장은 STT/TTS 기술을 “이론”이 아니라 **제품 설계 관점**으로 정리합니다.

---

### 2) 학습 목표

1. STT/TTS/실시간 음성 에이전트의 표준 파이프라인을 설명
2. WER/CER, RTF 같은 핵심 지표를 이해하고 운영 KPI로 변환
3. 최신 실무 솔루션(Whisper 계열, 클라우드 STT/TTS, 실시간 스트리밍 엔진)을 구분
4. 도메인 적응(용어 사전, 핫워드, 커스텀 vocab)과 후처리로 정확도를 올리는 방법 이해
5. 음성+LLM 결합 시 안전/지연/비용을 통제하는 아키텍처 설계

## 3) 핵심 개념: Speech AI 파이프라인 7단

음성 AI는 아래 7단으로 보면 대부분 설계가 끝납니다.

1. **오디오 수집(Ingest)**: 마이크/전화/파일, 샘플레이트/채널
2. **전처리(Preprocess)**: VAD(무음 제거), 노이즈 억제, 정규화
3. **ASR/STT**: 음성 인식(스트리밍/배치)
4. **후처리(Postprocess)**: 문장부호, 숫자/단위 표준화, 도메인 용어 보정
5. **NLP/LLM 처리(선택)**: 요약, 의도 분류, 상담 답변 생성, RAG/툴 호출
6. **TTS(선택)**: 음성 합성(스트리밍 가능 여부 중요)
7. **운영(Logging/PII/QA)**: 품질 평가, 샘플링 검수, 개인정보 처리

---

## 4) 핵심 원리 1: STT(ASR)의 품질은 “환경 + 도메인 + 후처리”에서 결정된다

### 4.1 WER/CER(평가 지표)

* **WER(Word Error Rate)**: (삽입+삭제+치환) / 단어 수
* **CER(Character Error Rate)**: 문자 단위 오류율(한글/중국어 등에서 유용)

**현업 팁**

* WER 자체보다 “핵심 엔티티 오류율”이 더 중요할 때가 많습니다.
  예: 제품명/고객명/금액/날짜가 틀리면 업무가 망함 → 엔티티 정확도를 별도 KPI로 둡니다.

### 4.2 스트리밍 vs 배치 STT

* **배치(Batch)**: 파일 전체를 처리 → 정확도 우선, 지연은 덜 중요(회의 녹취/자막)
* **스트리밍(Streaming)**: 실시간으로 부분 결과를 출력 → 지연 최우선(콜봇/대화)

스트리밍은 “부분 자막이 바뀌는 현상(수정, revision)”이 있으므로 UX 설계가 필요합니다.

### 4.3 도메인 적응(실무에서 가장 큰 효과)

* **용어 사전/커스텀 vocabulary**: 회사명/제품명/약어 등록
* **Hotwords/Boosting**: 특정 단어를 더 잘 인식하도록 가중
* **후처리 규칙**: 숫자/단위/코드/버전 표준화(예: “삼점오”→3.5)

대부분의 조직은 “모델 파인튜닝”보다 **사전+후처리**가 비용 대비 효과가 큽니다.

---

## 5) 핵심 원리 2: TTS는 ‘자연스러움’뿐 아니라 ‘일관성·지연·브랜딩’이 중요하다

### 5.1 TTS 품질 요소

* 발음 정확도(고유명사/영어/숫자)
* 억양/감정/속도/멈춤(프로소디)
* 화자 일관성(브랜드 음성)
* 스트리밍 가능 여부(대화형이면 필수에 가깝다)

### 5.2 TTS 실무 팁

* 긴 문장을 한 번에 합성하면 지연이 커짐 → 문장/절 단위 스트리밍 합성
* 숫자/단위/약어는 TTS 전처리(읽는 방식 표준화)가 매우 중요
  예: “1/2”, “10kg”, “v2.1.0” 같은 것들

## 6) 음성 에이전트(Voice Agent) 아키텍처: STT + LLM + TTS를 묶을 때 생기는 문제들

### 6.1 표준 구성(실시간)

1. 마이크 입력
2. **VAD**로 발화 구간 감지
3. **Streaming STT**로 텍스트 생성
4. (선택) **대화 상태** 업데이트 + **RAG/툴 호출**
5. 응답 텍스트 생성(LLM)
6. **Streaming TTS**로 음성 출력
7. 중간에 사용자가 끼어들면 **barge-in** 처리(말 끊기)

### 6.2 UX 핵심: 지연 예산(Latency budget)

대화형은 체감이 중요해서 “총 지연”을 쪼개 관리합니다.

* STT 지연
* LLM 생성 지연
* TTS 시작 지연
* 네트워크 지연

현업에서는 “모델 하나 교체”보다 파이프라인 최적화(스트리밍, 캐싱, 짧은 응답, 툴 최소화)가 효과가 큽니다.

### 6.3 안전/보안

* 녹취에는 개인정보가 많음 → 저장/마스킹/접근권한
* 음성 인젝션(특정 문구로 시스템을 속이는 것) 가능성
* 툴 호출(8장)과 결합 시 승인/allowlist/감사로그가 필수

---

## 7) 최신 기술/솔루션(실무 대표, 1~2줄 설명)

### 7.1 STT(ASR)

* **Whisper(및 faster-whisper)**: 다국어 STT에서 널리 쓰이며, 배치 녹취/자막에 특히 강함(자체 호스팅 가능).
* **NVIDIA Riva**: 스트리밍 ASR/TTS를 GPU 최적화로 제공(엔터프라이즈/실시간에 강점).
* **Google Cloud Speech-to-Text**: 스트리밍/배치 STT와 도메인 기능(커스텀 vocab 등)을 제공하는 관리형 서비스.
* **Azure Speech**: STT/TTS 통합 서비스로, 기업 환경과 연계가 쉬움.
* **AWS Transcribe**: 콜센터/스트리밍 STT 구성과 AWS 생태계 통합에 유리.

### 7.2 TTS

* **Azure Neural TTS / Google Cloud TTS / Amazon Polly**: 상용 관리형 TTS로 안정적 운영과 언어/음색 옵션 제공.
* **Coqui TTS(오픈소스)**: 자체 호스팅 기반 TTS 실험/커스터마이즈에 사용.
* **ElevenLabs(상용)**: 고품질 음성 합성과 다양한 음색/스타일 옵션으로 알려진 서비스 계열.

### 7.3 오디오 전처리/스트리밍

* **WebRTC**: 실시간 음성 스트리밍/저지연 통신 표준(브라우저/모바일).
* **RNNoise/노이즈 억제 계열**: 잡음 환경에서 인식 품질을 올리는 전처리 구성에 활용.
* **FFmpeg / GStreamer**: 오디오/비디오 스트림 처리의 표준 도구.

---

## 8) 평가/운영: Speech AI는 “샘플링 QA”가 필수다

### 8.1 핵심 운영 지표

* STT: WER/CER, 엔티티 오류율(고유명사/숫자), RTF(Real-time factor)
* TTS: MOS(주관 평가), 발음 오류율, 시작 지연
* Voice Agent: Turn latency(턴 응답 시간), barge-in 성공률, 오탐/미탐(의도 분류)

### 8.2 실무 운영 루프

* 실패 케이스 수집(용어/환경/화자)
* 용어 사전 업데이트
* 후처리 규칙 개선
* 필요 시 모델 교체/파인튜닝

## 9) 권장 실습(현업형)

### 실습 A: 회의 녹취 → 요약 → 액션아이템 추출

1. Whisper/faster-whisper로 STT
2. 문장부호 복원 + 숫자/단위 정규화
3. LLM으로 요약 + 액션아이템을 구조화(JSON)
4. Jira/ToDo로 등록(툴 호출)

**평가**: 액션아이템 누락률, 엔티티 오류율, 처리 시간

### 실습 B: 콜봇(스트리밍) 미니 프로토타입

1. WebRTC로 마이크 스트리밍
2. 스트리밍 STT
3. 짧은 응답 생성(temperature 낮게)
4. 스트리밍 TTS
5. barge-in(사용자 끼어들기) 처리

**평가**: 턴 지연, 중복/오답률, UX 만족도(간단 설문)
