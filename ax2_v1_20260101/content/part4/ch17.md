
## 17장. 이상탐지·예측·추천(비 LLM 특수 AI): “현업 데이터(시계열/로그/행동)”를 돈으로 바꾸는 최신 스택

### 1) 개요: LLM이 못하는 게 아니라, **LLM보다 더 효율적인 방법**이 많다

현업에서 “실제로 돈이 되는 AI”는 여전히 비 LLM 영역이 강합니다.

* **이상탐지(Anomaly Detection)**: 장애 조기 감지, 사기/부정, 품질 이상, 보안 이벤트
* **시계열 예측(Forecasting)**: 수요/매출/재고, 트래픽/용량, 장비 고장 예측
* **추천/랭킹(Recommender Systems)**: 개인화, 콘텐츠 추천, 검색 랭킹 개선
* **원인분석(RCA)**: “왜 이상이 발생했는지” 설명

이 장은 최신 트렌드(딥러닝 기반 시계열 모델, 자가학습/파운데이션 시계열, 실시간 스트리밍, 피처 스토어, 온라인 평가)와, “LLM을 어디에 끼우면 좋은지”까지 연결합니다.

---

### 2) 학습 목표

1. 이상탐지/예측/추천 문제를 “정확한 문제정의 + 지표 + 데이터 스키마”로 설계
2. 최신 모델 계열(딥러닝 시계열, 트랜스포머 기반 예측, self-supervised anomaly)과 전통 기법을 비교
3. 실시간/배치 파이프라인(피처, 서빙, 모니터링)을 구축하는 아키텍처를 이해
4. 데이터 드리프트/컨셉 드리프트를 감지하고 재학습/튜닝 루프를 설계(20장 연계)
5. 운영에서 중요한 “오탐/미탐 비용”과 알림 정책을 설계

---

## 3) 핵심 개념: 이 영역의 승부처는 “모델”이 아니라 **문제정의와 데이터**

### 3.1 이상탐지에서 자주 틀리는 지점

* 이상(Anomaly)의 정의가 애초에 불명확
* 라벨이 없는데 지도학습을 기대
* 오탐을 줄이려다 미탐이 급증(또는 반대)
* 운영에서 “정상 패턴”이 변함(컨셉 드리프트)

### 3.2 예측에서 자주 틀리는 지점

* 예측 목적이 불명확(일/주/월, 예측 지평)
* 지표 선택이 잘못됨(MAPE/SMAPE/Pinball 등)
* 데이터 누수(leakage): 미래 정보가 학습에 섞임
* 프로모션/이벤트 같은 외생 변수를 무시

### 3.3 추천에서 자주 틀리는 지점

* 오프라인 지표만 올리고 온라인에서 악화(편향/탐색 부족)
* 콜드스타트(새 사용자/새 아이템) 대응 부족
* 피드백 루프(추천→노출→클릭→데이터 편향)가 설계되지 않음

---

## 4) 이상탐지(Anomaly Detection): 실무 4가지 대표 패턴

### 4.1 규칙/통계 기반(가장 강력한 1차선)

* Z-score, EWMA, Holt-Winters, STL decomposition
* 장점: 빠르고 설명 가능, 운영 제어 쉬움
* 단점: 복잡한 패턴/다변량 상관은 약함

**현업 팁**: 처음부터 딥러닝으로 가지 말고, 규칙+통계를 베이스라인으로 두면 운영이 쉬워집니다.

### 4.2 예측 기반(Residual anomaly)

* “미래를 예측”하고, **실제값-예측값(잔차)**가 크면 이상
* 장점: 시계열에 강함, 임계값 운영이 쉬움
* 단점: 예측이 틀리면 이상도 틀림

### 4.3 재구성 기반(Autoencoder)

* 정상 데이터로 입력을 재구성하도록 학습
* 재구성 오차가 크면 이상
* 장점: 라벨 없이 학습 가능(정상만으로)
* 단점: 정상 분포가 바뀌면 오탐 증가

### 4.4 표현학습(Self-supervised) 기반

* Masking/Contrastive로 시계열 표현을 학습 후 이상 점수 산출
* “라벨 부족 + 패턴 복잡”한 산업 데이터에서 최근 많이 사용

---

## 5) 시계열 예측(Forecasting): 최신 모델 + 운영 감각

### 5.1 고전 모델(여전히 유효)

* ARIMA/SARIMA, ETS, Prophet(추세/계절성 분해)
* 장점: 작은 데이터/설명 가능/빠름
* 단점: 복잡한 다변량/비선형 상관은 제한

### 5.2 딥러닝 시계열(현업 채택 증가)

* **N-BEATS/N-HiTS**: 구조적으로 시계열 분해를 학습해 강력한 성능을 내는 계열
* **DeepAR**: 확률 예측(분포)을 다루는 접근
* **Temporal Fusion Transformer(TFT)**: 외생 변수와 해석 가능성을 강조한 Transformer 기반 예측
* **PatchTST**: 시계열을 패치 단위로 보고 Transformer로 예측하는 계열(최근 성능 경쟁에서 자주 등장)

### 5.3 “파운데이션 시계열(Foundation models for TS)”

최근에는 대규모 시계열 사전학습 기반 모델이 등장하며,

* 다양한 도메인에서 제로샷/소량 데이터 적응을 노립니다.
  다만 현업에서는 “데이터 특성/평가”가 더 중요해서,
* 무조건 최신이라고 정답은 아니고, 베이스라인 대비 이득을 검증해야 합니다.

### 5.4 운영 지표(현업 필수)

* 점 예측: MAE/RMSE/SMAPE
* 확률 예측: Pinball loss(Quantile), CRPS
* 사업 지표: 재고 품절률, 과잉 재고 비용, SLA 위반률

---

## 6) 추천/랭킹(Recsys): “오프라인 점수”보다 “온라인 실험”이 본게임

### 6.1 추천 시스템의 2단 구조(표준)

1. **Candidate Generation(후보 생성)**

   * 사용자에게 보여줄 “수백~수천 개 후보”를 빠르게 뽑기
2. **Ranking(정렬)**

   * 후보를 다시 점수화해 최종 Top-N 결정

### 6.2 대표 모델 계열(최신 실무)

* **Two-tower / Dual encoder**: 사용자/아이템 임베딩을 따로 만들고 내적으로 후보 검색(대규모에 강함)
* **Matrix Factorization(Implicit)**: 여전히 강력한 베이스라인(특히 암묵 피드백)
* **Wide & Deep / DeepFM**: 범주형 피처가 많은 추천에서 전통적으로 강력
* **Transformer 추천(SASRec, BERT4Rec)**: 시퀀스(최근 행동)를 모델링하는 데 강함

### 6.3 온라인 실험(A/B)과 탐색

* CTR만 올리면 장기적으로 다양성이 떨어지고 품질이 악화될 수 있음
* **탐색-활용(Explore-Exploit)**: bandit, epsilon-greedy, Thompson sampling 등
* 목표 지표를 단기(CTR) + 중장기(리텐션/구매)로 분리하는 게 중요

---

## 7) “LLM은 어디에 쓰나?”(비 LLM 영역과의 결합 포인트)

LLM은 이 영역에서 “예측 모델”을 대체하기보다 **설명/운영/피처**에 강합니다.

* 알림/이상 이벤트에 대한 **자연어 RCA 요약**(로그/대시보드 근거 기반)
* 피처 정의/SQL 생성/데이터 품질 검사 자동화(단, 검증 필수)
* 알림 정책 문서화, 운영자 Runbook 자동 생성
* 사용자 피드백/리뷰 텍스트를 요약해 추천 피처로 활용

---

## 8) 배포/운영 아키텍처: 실시간 vs 배치

### 8.1 배치(Batch)

* 하루 1회 예측/추천 생성 → DB 저장 → 서비스는 조회만
* 장점: 안정/비용 효율
* 단점: 최신성 낮음

### 8.2 실시간(Online)

* 스트리밍 이벤트(Kafka 등) → 실시간 피처 계산 → 온라인 서빙
* 장점: 최신 행동 반영(추천/사기탐지에 중요)
* 단점: 복잡도/운영 비용 증가

### 8.3 공통 핵심 구성요소

* **Feature Store(Feast 등)**: 온라인/오프라인 피처 일관성
* **모델 서빙**: Triton/KServe/BentoML/Ray Serve 등
* **모니터링**: 지표 드리프트, 데이터 품질, 알림 오탐/미탐

---

## 9) 관련 기술·솔루션(최신 실무 스택, 1~2줄)

### 9.1 시계열/예측 라이브러리

* **Nixtla(StatsForecast/NeuralForecast)**: 통계+딥러닝 시계열 모델을 실무적으로 다루기 쉽게 제공.
* **Darts**: 다양한 예측 모델을 통합한 파이썬 시계열 프레임워크.
* **GluonTS**: 확률 예측과 딥러닝 시계열 모델(DeepAR 등) 생태계.

### 9.2 이상탐지

* **PyOD**: 다양한 이상탐지 알고리즘을 모은 라이브러리(빠른 베이스라인).
* **Alibi Detect**: 드리프트/이상탐지 등 모니터링 도구로 활용.

### 9.3 추천/랭킹

* **TensorFlow Recommenders(TFRS)**: 추천 파이프라인과 모델 구성에 유용.
* **TorchRec**: 대규모 추천을 위한 PyTorch 기반 컴포넌트.
* **Faiss / ScaNN**: 대규모 후보 검색(ANN)에서 자주 사용.

### 9.4 스트리밍/서빙/피처

* **Kafka / Flink / Spark Streaming**: 실시간 이벤트 처리.
* **Feast**: Feature Store(온라인/오프라인 피처 정합성).
* **MLflow**: 실험/모델 레지스트리/배포 연결에 널리 사용.

---

## 10) 권장 실습(현업형)

### 실습 A: 서비스 지표 이상탐지 + 알림 정책

1. 서비스 지표(예: latency, error rate) 시계열 수집
2. STL 분해 + 잔차 기반 이상탐지(베이스라인)
3. 오탐/미탐 비용 기준으로 임계값과 cooldown 설계
4. 알림 이벤트를 JSON으로 저장하고, LLM으로 “RCA 요약” 생성(근거 포함)

### 실습 B: 수요 예측 + 재고 비용 KPI

1. 예측 지평(7일/30일)과 KPI 정의
2. 베이스라인(ETS/Prophet) + 딥러닝(N-HiTS/TFT 중 하나) 비교
3. Pinball(quantile)로 안전재고를 위한 구간 예측
4. 비용(품절/과잉) 기반 평가표 작성

### 실습 C: 추천(후보+랭킹) 미니 파이프라인

1. Two-tower로 후보 생성 + ANN 검색(Faiss)
2. 간단 랭커로 재정렬
3. 오프라인 지표(Recall@K, NDCG) + 온라인 시뮬레이션(탐색 포함)

## 11) 이 장의 결론(다음 장 연결)

* 이상탐지/예측/추천은 최신 AI 트렌드 속에서도 “현업 가치”가 큰 비 LLM 핵심 영역입니다.
* 성공은 모델보다 **문제정의, 지표, 데이터 품질, 실시간 파이프라인, 드리프트 대응**에서 갈립니다.
* 다음 23장에서는 이런 비 LLM 모델과 LLM/RAG/에이전트를 함께 운영할 때 필요한 **데이터 드리프트/모델 모니터링/재학습 자동화**를 더 깊게 들어가면 커리큘럼이 완성도가 높아집니다.
