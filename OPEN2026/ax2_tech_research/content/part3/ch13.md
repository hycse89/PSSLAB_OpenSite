
## 13장. Video AI(비디오): “프레임 비전 + 시간축”으로 추적·행동·이벤트를 이해하고 운영하기

### 1) 개요: 비디오는 이미지보다 어렵고, 그래서 더 큰 가치가 나온다

비디오 AI는 단순히 “이미지 모델을 프레임마다 돌리는 것”에서 시작하지만, 실무에서 진짜 가치는 **시간 축을 이해**하는 데서 나옵니다.

* **추적(Tracking)**: 같은 객체를 시간에 따라 동일 ID로 연결 → 카운팅/동선/침입 감지의 기반
* **행동 인식(Action Recognition)**: 사람이/물체가 “무엇을 하는지” 분류
* **이벤트 감지(Event Detection)**: 특정 조건(침입, 넘어짐, 위험행동, 라인 정체)을 “언제 발생했는지” 판단
* **실시간 스트리밍 운영**: 디코딩/지연/프레임 드랍/비용/엣지 배포가 승부처

이 장은 “모델 성능”보다, **파이프라인 설계(디코딩→검출→추적→시간 집계→알림)**와 **운영 품질(지연/정확/오탐/미탐)**에 초점을 둡니다.

---

### 2) 학습 목표

1. 비디오 문제를 **(검출+추적)**, **행동 인식**, **이벤트 감지**로 분해해 설계
2. 추적 지표(**MOTA/IDF1/HOTA**)와 실무 임계값(알림 기준)을 설정
3. 최신 실무 스택(예: YOLO + ByteTrack, DeepStream, GStreamer/FFmpeg, Triton/TensorRT)을 이해
4. 스트리밍 환경에서 지연/처리량/프레임 드랍을 통제하는 배포 전략 수립
5. 오탐/미탐을 줄이는 “시간축 필터링(temporal smoothing)”과 규칙/모델 결합을 적용

---

## 3) 핵심 개념: Video AI를 4단으로 나눠 생각하라

비디오 AI는 보통 아래 4단 구조로 이해하면 설계가 쉬워집니다.

1. **Per-frame 인지(Detection/Segmentation)**

* 프레임에서 객체/영역을 인식 (12장 내용이 기반)

2. **시간 연결(Tracking)**

* 프레임 간 동일 객체를 연결해 ID 유지

3. **시간적 해석(Temporal reasoning)**

* 일정 시간 동안의 움직임/상태 변화를 모아서 행동/이벤트 판정

4. **운영/알림(Serving & Alerting)**

* 실시간 지연/오탐 억제/감사 로그/재현성 확보

> 실무 결론: “비디오 모델 하나”로 끝내려 하면 실패합니다.
> 대부분은 **검출+추적+시간집계+규칙/분류기** 조합이 더 강합니다.

---

## 4) 핵심 원리 1: 추적(Tracking)의 본질은 “연결(association)”이다

추적은 보통 다음의 조합 문제입니다.

* 각 프레임에서 검출된 박스들이 있을 때,
* 이전 프레임의 어떤 ID와 “같은 객체”인지 연결

### 4.1 MOT(다중 객체 추적) 기본 구성

* **Detector**: 매 프레임 객체 박스 생성 (예: YOLO, RT-DETR 등)
* **Motion model**: 이전 위치로 다음 위치를 예측 (보통 Kalman Filter)
* **Association**: 예측과 새 검출을 매칭 (IoU 거리 + 특징 거리 + Hungarian 알고리즘)
* **ReID(선택)**: 사람이 가려졌다가 나타나도 같은 사람인지 식별(StrongSORT류)

### 4.2 추적 품질을 좌우하는 변수(실무 포인트)

* 검출기의 **미탐**이 추적을 끊습니다(가장 흔한 실패 원인)
* 가림(occlusion), 군중, 카메라 흔들림, 모션 블러는 난이도를 급상승시킵니다
* FPS가 낮거나 지연이 크면 association이 불안정해집니다

---

## 5) 핵심 원리 2: 시간 축 해석은 “누적 + 필터링”이 기본이다

비디오에서 오탐을 줄이는 가장 강력한 방법 중 하나는 **시간 축으로 누적해 판단**하는 것입니다.

* 단일 프레임에서 “안전모 없음”이 나와도 바로 알림 → 오탐 폭발 가능
* **N프레임 중 M프레임 이상** 조건을 만족할 때 알림 → 안정성 상승
* 이벤트는 대부분 “순간”이 아니라 “구간”입니다(침입/넘어짐/정체 등)

### 5.1 흔히 쓰는 시간 필터링 패턴

* **Temporal smoothing**: 최근 K프레임 평균/다수결로 클래스 안정화
* **Debounce / Cooldown**: 알림 후 일정 시간 중복 알림 억제
* **State machine**: “대기→의심→확정→종료” 같은 상태 전이로 이벤트 판정

---

## 6) 대표 문제 유형과 접근법(현업 기준)

### 6.1 실시간 감시/안전(침입, PPE, 위험행동)

* 접근: **검출(사람/헬멧/조끼) + 추적 + 규칙(ROI 침입, 지속시간)**
* 장점: 학습 데이터가 적어도 규칙으로 상당히 해결 가능

### 6.2 카운팅/혼잡도/대기열

* 접근: 추적 기반 카운팅(라인-crossing) + 혼잡도 추정(ROI 내 객체 수)
* 핵심: ID 스위치 줄이기 + “중복 카운팅 방지” 로직

### 6.3 행동 인식(넘어짐, 폭력, 작업동작)

* 접근 A(가벼움): 추적 + 포즈/키포인트 + 간단 분류(시간 특징)
* 접근 B(모델 기반): 3D CNN/Video Transformer로 클립 단위 분류
* 실무 팁: 넘어짐 같은 건 **포즈 기반**이 데이터 효율이 좋은 경우가 많습니다.

### 6.4 이상탐지(정의하기 어려운 이상)

* 접근: 정상 패턴 학습(오토인코더/예측 기반) + 임계값
* 실무 팁: “이상” 정의가 바뀌므로 운영·재학습 루프가 중요(22~23장과 연결)

## 7) 모델/기술 스택(최신 실무 중심)

### 7.1 검출(Per-frame)

* **Ultralytics YOLO(예: YOLOv8/YOLOv9 계열)**: 실시간성/배포 편의로 가장 자주 선택되는 라인.
* **RT-DETR 계열**: Transformer 기반 실시간 검출 변형으로 특정 조건에서 강점.

### 7.2 추적(MOT)

* **ByteTrack**: “검출 점수 낮은 박스까지” 활용해 추적 끊김을 줄이는 실무 인기 트래커.
* **DeepSORT / StrongSORT**: ReID 특징을 써서 가림/재등장 상황에서 ID 유지에 도움.
* **BoT-SORT**: SORT 계열 개선으로 다양한 환경에서 강력한 성능을 보이는 트래커 라인.

### 7.3 포즈/키포인트(행동 인식의 강력한 대안)

* **OpenPose / MMPose**: 사람 관절 키포인트를 추정해 넘어짐/위험자세 같은 행동 판정에 활용.

### 7.4 비디오 행동 인식/이해(클립 기반)

* **SlowFast / X3D**: 3D CNN 계열로 효율과 성능의 균형을 잡은 대표 구조.
* **TimeSformer / VideoMAE**: Video Transformer/마스킹 기반 사전학습 계열로 대규모 데이터에서 강점.
* **MMAction2**: 행동 인식/검출 모델과 데이터 파이프라인을 폭넓게 제공하는 프레임워크.

---

## 8) 평가 지표: Video AI는 “정확도+연속성+운영”을 함께 본다

### 8.1 추적 지표(MOT)

* **MOTA**: 미탐/오탐/ID스위치를 종합(해석이 쉽지만 한계도 있음)
* **IDF1**: ID 유지(연속성)에 초점
* **HOTA**: 검출+연결을 균형 있게 평가하려는 지표

실무에서는 지표만 보지 말고,

* “카운팅 오차”, “알림 오탐률/미탐률”, “ID switch가 실제 기능에 미치는 영향”을 함께 봅니다.

### 8.2 행동/이벤트 지표

* 행동 분류: Top-1/Top-5 accuracy, F1
* 이벤트 감지: Precision/Recall, 구간 단위 mAP(Temporal IoU 기반)
* 알림 운영: 시간당 오탐 수, 평균 탐지 지연, 중복 알림 수

---

## 9) 실시간 스트리밍 파이프라인(현업 표준 아키텍처)

비디오 AI는 모델보다 **파이프라인**이 성패를 가릅니다.

### 9.1 표준 구성

1. **Ingest/Decode**: RTSP/HLS 파일/스트림 수집 및 디코딩
2. **Preprocess**: 리사이즈, ROI 크롭, 프레임 샘플링(예: 30fps→10fps)
3. **Detector**: GPU 추론(배치/동시성 고려)
4. **Tracker**: CPU/GPU로 ID 부여
5. **Temporal aggregator**: 시간 조건 필터링, 상태 머신, 이벤트 규칙/분류기
6. **Output**: 이벤트 JSON, 클립 저장, 대시보드, 알림(슬랙/문자)
7. **Observability**: 지연/FPS/드랍/오탐률 로깅

### 9.2 지연 최적화 핵심 포인트

* 디코딩이 병목인 경우가 많습니다 → 하드웨어 디코더/파이프라인 최적화 필요
* 프레임을 모두 처리하지 말고 **샘플링**(예: 5~10fps)으로 비용 절감 가능
* 모델은 ONNX/TensorRT로 최적화하고, Triton 같은 서빙으로 배치 효율을 확보

---

## 10) 관련 기술·솔루션(실무에서 자주 쓰는 것들)

* **FFmpeg / GStreamer**: 스트리밍 수집·디코딩·전처리의 사실상 표준.
* **NVIDIA DeepStream**: 비디오 분석 파이프라인(디코딩→추론→추적→메타데이터)을 GPU 친화적으로 구성.
* **OpenCV**: 프레임 처리/ROI/후처리에서 여전히 유용.
* **Triton Inference Server**: 검출/행동 모델을 안정적으로 서빙(배치/동시성/모델 관리).
* **TensorRT / ONNX Runtime**: 실시간 추론 최적화의 대표 스택.
* **Kafka / Redis Streams(선택)**: 이벤트 스트림 처리/버퍼링/비동기 파이프라인에 활용.

## 11) 권장 실습(현업형): “검출+추적+시간 조건”으로 완성도 높이기

### 실습 A: 침입 감지(ROI) + 알림 안정화

1. 사람 검출(YOLO)
2. ByteTrack으로 ID 추적
3. ROI(금지 구역) 내부에 **N초 이상** 머무르면 이벤트 발생
4. Cooldown 적용(중복 알림 방지)
5. 평가: 시간당 오탐 수, 탐지 지연, 누락률

**산출물**: “알림 정책 테이블”(N초, M프레임, cooldown) + 운영 지표 리포트

### 실습 B: 라인 크로싱 카운팅(출입 인원)

1. 검출 + 추적
2. 가상의 라인을 넘는 ID를 카운팅
3. ID 스위치가 카운팅에 주는 영향을 분석하고 보정 로직 적용

### 실습 C: 넘어짐 감지(포즈 기반)

1. 사람 검출 후 키포인트 추정(OpenPose/MMPose)
2. 자세 특징(기울기/관절 높이 변화)을 시간축으로 누적
3. 간단 분류기/규칙으로 이벤트 감지
4. 평가: 오탐/미탐 + 탐지 지연

## 12) 이 장의 결론(다음 장과 연결)

* Video AI는 “이미지 모델을 많이 돌리는 것”이 아니라 **시간 축을 설계하는 일**입니다.
* 성공은 모델보다 **파이프라인(디코딩/지연), 추적 안정화, 시간 조건 필터링, 운영 지표**에서 갈립니다.
* 다음 14장(Document AI)은 비정형 문서를 “구조화 데이터”로 바꾸는 영역으로, 비디오처럼 **전처리/구조화/평가**가 성패를 좌우하는 분야로 이어집니다.
