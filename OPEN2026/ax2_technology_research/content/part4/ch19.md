
## 19장. 도메인 특화(의료/금융/제조 등) 적용 패턴: “모델”보다 **규정·데이터·검증·운영**이 성패를 가른다

### 1) 개요: 도메인 특화 AI는 ‘정확도’가 아니라 **리스크 비용**과 **감사 가능성**의 게임

의료/금융/제조 같은 영역은 공통점이 있습니다.

* **오류 비용이 크다**(사람/돈/품질/안전)
* **규정·감사·증적**이 필수다(누가/왜/근거는?)
* **데이터가 더럽고 편향되어 있다**(현장/기관/장비/고객군 차이)
* “최신 모델”보다 **운영 체계**가 성능을 이긴다

이 장은 “도메인별로 무엇이 다르고, 무엇은 같은지”를 **재사용 가능한 패턴(templates)**로 정리합니다.

---

## 2) 학습 목표

1. 도메인 AI 프로젝트를 **리스크 등급화 → 요구사항 → 데이터/평가 → 배포/운영**으로 구조화
2. 의료/금융/제조에서 반복되는 **필수 통제(근거/검증/승인/로그)**를 설계
3. 도메인별 대표 유스케이스를 “추천 아키텍처”로 제시
4. 데이터 부족/라벨 비용/드리프트 문제를 해결하는 실무 전략 수립
5. 컴플라이언스(개인정보/감사/설명가능성) 요구를 기술 설계로 연결

---

# A. 공통 적용 프레임(모든 도메인에 통하는 7단 패턴)

## A1) 유스케이스 리스크 등급화(필수)

* **Low**: 내부 분석/요약/검색(오류 영향 제한적)
* **Medium**: 업무 자동화(문서 처리, 상담 지원)
* **High**: 안전/금융거래/진단·판단(오류 시 큰 피해)

**결정 규칙**

* 사람/돈/안전에 직접 영향? → High로 보고 시작
* “자동 실행”이 있나? → High 또는 HITL 필수

## A2) 요구사항을 “정답률”이 아니라 “오탐/미탐 비용”으로 정의

* 의료: 미탐이 치명적(암/응급), 오탐은 과잉 검사 비용
* 금융: 오탐(정상 거래 차단)이 UX/이탈을 만든다
* 제조: 오탐은 폐기·재작업 비용, 미탐은 불량 유출/리콜 비용

## A3) 데이터 전략: 도메인별 “골든 소스”를 먼저 확보

* 데이터 계보(lineage): 수집→가공→라벨→학습→배포까지 추적
* 라벨 가이드(룰북): 기준 흔들리면 모델이 흔들림(12·14장과 동일)

## A4) 모델 전략: “최신”보다 “재현 가능 + 튜닝 가능”이 우선

* 베이스라인(규칙/통계/전통 ML) → 딥러닝/LLM은 그 다음
* 중요한 건 **검증 가능성**(왜 그런 결론인지 추적 가능)

## A5) 검증/가드레일: 구조화 출력 + 규칙 검증 + 승인(HITL)

* LLM 출력은 **JSON Schema/Pydantic**로 검증(7장)
* 고위험은 **2단계 실행(초안→승인→반영)**(18장)
* 결과는 **근거(문서/좌표/로그)**를 남겨 감사 가능하게(14·19장)

## A6) 평가/회귀: 도메인별 골든셋 + 레드팀

* 골든셋은 “정답”만이 아니라 **근거/행동/금지 규칙**까지 포함(19장)
* 변경(모델/프롬프트/인덱스/룰)마다 회귀 테스트(19장)

## A7) 운영: 드리프트 감지 + 재학습/재인덱싱 루프

* 환경이 바뀌면 성능이 무너진다(23장)
* 도메인별로 드리프트 원인이 다르므로 모니터링 지표가 달라짐

# B. 의료(Healthcare) 적용 패턴

## B1) 대표 유스케이스

1. **의료 문서 요약/코딩 보조**: 진료 기록, 소견서, 보험 청구 코드 추천
2. **영상/검사 보조**: X-ray/CT/MRI 이상 소견 후보 제시(최종 판단은 의사)
3. **환자 상담/문진 보조**: 증상 체크리스트, 안내(응급 분류는 특히 고위험)

## B2) 의료 도메인 핵심 요구사항(실무 체크)

* 개인정보: 환자 식별정보(PII) + 의료정보(민감정보) 처리(마스킹/접근통제)
* **근거 중심**: 어떤 소견/문장/영상 근거로 결론을 냈는지
* 안전: “진단 확정”이 아니라 **의사결정 보조**로 역할 제한
* 데이터 편향: 기관/장비/프로토콜 차이(드리프트 빈번)

## B3) 권장 아키텍처(패턴)

* (문서) OCR/파싱 → RAG(병원 지침/가이드라인) → LLM 요약/구조화 → **의학 용어/코드 검증 룰** → 의사 승인
* (영상) 검출/분할(12장) → “후보 영역” + 설명 텍스트 생성 → 판독 UI에 근거(좌표) 표시 → 승인/피드백 수집

## B4) 평가 지표

* 문서: 요약 정확도(루브릭), 누락(중요 항목), 환각률(근거 밖 주장)
* 영상: 민감도/특이도, F1, 임상적으로 의미 있는 false negative 감소
* 운영: 케이스별 위험도 분류의 적절성, “의사 수정 시간 감소”

# C. 금융(Finance) 적용 패턴

## C1) 대표 유스케이스

1. **사기/부정 탐지**(이상탐지/그래프/시계열)
2. **신용/리스크 평가 보조**(설명 가능한 피처 + 정책 룰)
3. **상담/규정 Q&A**(RAG 기반, 인용 필수)
4. **문서 처리**(KYC, 계약서/신분증/증빙 서류 추출)

## C2) 금융 도메인 핵심 요구사항

* 규정 준수/감사: 왜 이 거래를 막았는지, 왜 이 점수를 줬는지
* **오탐 비용**이 매우 큼: 정상 고객 차단 → 이탈/민원
* 공격자 적응: 사기 패턴은 계속 진화(컨셉 드리프트가 상수)
* 보안: 계정/거래 정보 유출 방지, 접근통제(18장)

## C3) 권장 아키텍처(패턴)

* 사기탐지: 스트리밍 이벤트 → 피처 계산(Feature Store) → 탐지 모델(22장) → 룰/임계값 정책 → **케이스 관리(HITL 조사)** → 피드백으로 재학습(20·23장)
* 규정 Q&A: ACL 포함 RAG → 답변은 **근거 인용 강제** + “확실/불확실” 표시 → 로그/감사 저장

## C4) 평가 지표

* 사기탐지: Precision/Recall + “차단 금액/오탐 손실” 같은 비용 기반 KPI
* 상담: 정답률보다 **근거 적합률/오답 시 리스크**(금융은 오답이 치명적)
* 운영: 드리프트 탐지 시간, 재학습 사이클 시간

# D. 제조(Manufacturing) 적용 패턴

## D1) 대표 유스케이스

1. **품질 검사(Vision)**: 결함 검출/분할, 불량 분류, 치수 측정
2. **예지 보전(PdM)**: 센서 시계열로 고장 예측/이상 탐지
3. **공정 최적화**: 수율/불량률 예측, 공정 파라미터 추천
4. **현장 안전(Video)**: PPE/침입/위험행동 이벤트 감지

## D2) 제조 도메인 핵심 요구사항

* 데이터 편차: 라인/장비/조명/카메라 교체로 분포가 쉽게 바뀜(드리프트 상수)
* 라벨 비용: 결함 라벨링이 어렵고, 불량이 희귀(불균형 심함)
* 실시간/엣지: 네트워크 제약, 지연 요구(25장과 강하게 연결)
* 측정: “정확도”보다 **불량 유출률(미탐)**을 극도로 싫어하는 경우가 많음

## D3) 권장 아키텍처(패턴)

* 비전 검사: 카메라 입력 → 검출/분할(12장) → 결함 면적/좌표 산출 → **판정 룰(등급/임계값)** → MES/QMS 연동(툴)
* 예지보전: 센서 스트림 → 이상탐지(22장) → 경보 정책(쿨다운) → 정비 티켓 발행(툴) → 결과 피드백으로 모델 개선(20·23장)
* 안전 감시: 엣지에서 검출/추적/이벤트(13·25장) → 클라우드는 클립/메타데이터만 저장

## D4) 평가 지표

* 비전: 미탐률(불량 유출), 오탐률(재작업/폐기), 라인별 성능 편차
* 예지보전: 탐지 지연, 오탐 경보/시간, MTBF 개선, 정비 비용 절감
* 운영: 카메라/조명 변경 시 성능 회복 시간(드리프트 대응)

# E. 도메인 특화에서 “항상” 필요한 공통 솔루션/기술 스택(요약)

### 데이터/품질/검증

* **Label Studio**: 라벨링/검수 워크플로우(문서/이미지/비디오)
* **Great Expectations**: 데이터 품질 검증 게이트(스키마/범위/결측)
* **JSON Schema / Pydantic**: 구조화 출력/툴 인자 검증(특히 금융/의료)

### 운영/평가/감사

* **OpenTelemetry + Grafana**: 지연/실패/비용/품질 지표 관측
* **promptfoo / OpenAI Evals**: 회귀/레드팀 테스트(19장)
* **OPA(Open Policy Agent)**: 정책(권한/툴 실행) 강제(18장)

### 배포/현장

* **Triton / TensorRT / ONNX Runtime**: 고성능 추론/최적화(17장)
* **Edge 스택(DeepStream, GStreamer, OTA 도구)**: 제조/현장에 자주 필요(25장)

## “실무 체크리스트”(이 장의 요약)

도메인 특화 프로젝트 시작 시 아래 10개만 먼저 확정해도 실패 확률이 크게 줄어듭니다.

1. 리스크 등급(자동 실행 여부 포함)
2. 오탐/미탐 비용과 목표 KPI
3. 데이터 소유자/권한/보존 정책(PII 포함)
4. 라벨 룰북(정의/경계/예외)
5. 베이스라인(규칙/통계/전통 ML)
6. 근거/감사 요구(인용, 좌표, 로그 수준)
7. 검증/승인(HITL) 조건
8. 골든셋 + 회귀 게이트(배포 조건)
9. 드리프트 모니터링 지표(도메인별)
10. 재학습/재인덱싱 트리거와 롤백 절차
