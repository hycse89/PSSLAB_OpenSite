AITL: “모델”이 아니라 “시스템”

AITL은 AI가 실행을 주도하더라도, 검증(Verifier)·게이트·예외/안전/관찰이 내장된 상태에서만 자동 실행을 허용합니다.

DEFINITIONAITL 운영적 정의최소요건
  • 자동 실행은 PASS 케이스에만 허용
  • REVIEW는 사람에게 라우팅(예외 큐)
  • FAIL은 중단/차단(정책·정합 위반)
  • Kill-switch/롤백/관찰가능성 없으면 AITL 금지
SCOPEGuarded Scope처음부터 전면 자동화 금지
  • 정상 케이스를 좁게 정의
  • 입력 타입/대상/환경을 제한
  • 지표 안정 시 범위를 확장
ARCHAITL 표준 아키텍처6요소 블록
VERIFIER레이어 스택결정론적 장치
  • 스키마/형식
  • 정합성/제약
  • 정책/컴플라이언스
  • 품질 체크(핵심)
  • 샘플링/리그레션
REASON사유 코드운영 공용어
  • 왜 REVIEW/FAIL인가
  • 개선 우선순위 근거
  • 드리프트 감지 신호
KEY성공 조건전수 재검증 제거
  • PASS는 자동 실행
  • 예외만 사람이 처리
  • 예외는 데이터로 환류
RULE공식 선언(방어 문장)AITL의 최소 기준

로그/지표/재현(감사)이 확보되지 않는 자동 실행은 AITL로 인정하지 않는다.
이는 모델 성능이 아니라 책임/운영의 최소 요건이다.
