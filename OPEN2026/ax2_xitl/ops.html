Ops & Safety: 운영이 AITL의 본체

정상 케이스가 아니라 예외에서 성공/실패가 갈립니다. 예외를 다루는 체계(큐/중단/롤백/관찰/드리프트)가 없으면 AITL은 곧 금지됩니다.

EX예외 분류운영 언어
  • Input(누락/오염)
  • Policy(민감/권한)
  • Model(불확실/모순)
  • Execution(API/DB)
  • Operational(드리프트)
SAFE안전장치 4종Fail-safe
  • 에스컬레이션
  • Kill-switch(중단)
  • Rollback(되돌림)
  • Safe Mode(레벨 다운)
OBS관찰가능성감사/재현
  • trace_id
  • version_set
  • reason_code
  • 트랜잭션/실행 로그
PIPE예외 처리 파이프라인(7단계)Detect → Feedback

예외는 버그가 아니다. 예외는 운영 설계의 일부이며, 예외 처리 결과가 Verifier/정책/입력 게이트로 환류될 때 성숙도가 올라간다.

METRICS핵심 운영지표대시보드 최소셋
  • PASS/REVIEW/FAIL 비율
  • 예외 처리 리드타임
  • 치명 오류율/롤백 빈도
  • 사유 코드 TOP N 추이
  • 안전모드 전환 횟수
LEVEL레벨 업/다운 규칙감이 아니라 지표
  • 안정 → 범위 확장(Guarded Scope) 또는 레벨 업
  • 급변/사고/드리프트 → Kill-switch + 안전모드(L3→L2)
  • 관찰가능성 상실 → 자동 실행 금지(즉시 다운)
