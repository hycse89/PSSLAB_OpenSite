Toolkit: 현장에서 바로 쓰는 xITL 레시피

패턴(성공 구조) + 안티패턴(실패 구조) + 템플릿/체크리스트(실행 도구) + 용어집(공용어)로 “방법론을 운영 가능한 표준”으로 만든다.

PATTERNS대표 패턴(16장)재사용 가능한 레시피
A/B HITL
초안→비평→개선 / 대안 비교 / 체크리스트 검토
C/D AITL
스키마 추출·정규화 / 분류·라우팅 / 예외 중심 운영 / 샘플링 감사
E 운영/진화
안전모드 / 리그레션 게이트 / 사유 코드 기반 개선
ANTI안티패턴 TOP(17장)조기 차단
  • Verifier 없는 자동 실행
  • 전수 재검증 지옥(이중 비용)
  • 예외 큐 부재
  • Kill-switch/롤백 부재
  • 관찰가능성 부재
  • 파일럿 성공 후 빅뱅 확장
TEMPL템플릿(18장)문서 표준
  • T1 의도 정의
  • T2 컨텍스트 패킷
  • T9 업무 명세
  • T11 Verifier 설계
  • T12 예외 런북
  • T14 관찰가능성 스펙
CHECK체크리스트(19장)실행 스위치
  • HITL: 의도/검토/기록
  • AITL: 최소요건
  • Verifier: 3상태+사유코드
  • Ops: 큐/중단/롤백
  • Scale: 확장 게이트
GLOSS용어집(20장)논쟁 방지
  • 신뢰 vs 검증
  • 자동화 vs 무검증 실행
  • 예외 vs 버그
  • SRE/QA/리스크 프레임 매핑
MESSAGE최종 5문장(공식 메시지)조직 공유용

1) HITL은 효율화, AITL은 검증 가능한 자동화다.
2) AITL의 기반은 신뢰가 아니라 Verifier(PASS/REVIEW/FAIL)다.
3) 자동 실행은 예외/중단/롤백/관찰가능성이 있을 때만 허용한다.
4) 레벨 다운은 실패가 아니라 안전장치의 정상 동작이다.
5) AI는 R이 될 수 있지만 A가 될 수 없고, 책임은 인간이 가진다.
